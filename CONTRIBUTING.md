# Contributing

## Before proposing a change

- Discuss substantial changes with the maintainers first.
- Keep each change focused and explain its security and compatibility impact.
- Add or update tests for changed contract behavior.
- Do not include credentials, private operational procedures, user data, generated binaries, or unrelated source.

## Review expectations

Contract changes require independent review before any production use. A passing local test suite is not a security audit. Do not add automated production deployment or signing steps without explicit maintainer approval.

## Pull requests

Include a concise summary, the behavior changed, test results, and any known risks. Never include private keys, signed transactions, or production-only configuration.
